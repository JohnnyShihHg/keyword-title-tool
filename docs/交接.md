# 交接（2026-11-20 更新）

給接手維護「關鍵時刻」剪輯工具的人。使用者看的說明在 [使用說明.md](使用說明.md)，這份是開發面的。

## 專案結構

Tauri 2 桌面程式，兩個 Rust crate ＋ 純 JS 前端：

| 位置 | 內容 |
|---|---|
| `core/` (`keyword-title-core`) | 不碰 UI 的邏輯。`core/src/autocut/plan.rs` 切段規劃、`titles.rs` OCR 對文稿、`stills.rs` 靜圖比對、`timecode.rs` 文稿時間 |
| `app/src-tauri/` (`keyword-title-tool`) | Tauri 殼。`src/autocut.rs` 監看器（讀側錄檔、掃描、規劃、出片、往前找開頭）、`main.rs` |
| `app/src/` | 前端：`autocut.js`（自動切段頁、時間欄數字轉換）、`bars.js`（壓 BAR）、`masks.js`（手動遮罩）、`stills.js`、`video.js`、`app.js`、`index.html`、`styles.css` |
| `docs/使用說明.md` | 畫面上只放一句話說明，詳細的都寫這裡 |

## 建置與發版

AI 的規則在 [AGENTS.md](../AGENTS.md)（`CLAUDE.md` 只有一行 `@AGENTS.md`，兩邊共用）。

```powershell
./scripts/check.ps1     # cargo test --workspace＋clippy（警告＝錯誤）＋eslint（要先裝 node，第一次會 npm install）
./scripts/golden.ps1    # 切段＋遮蓋回歸比對，見下方「golden 測試」
cargo build -p keyword-title-tool
```

發版（**只在使用者說「發版」時才發**）：`scripts/release.sh X.Y.Z "修正：…；改善：…"`（Git Bash）。腳本會：

1. `git fetch --tags`，遠端比較新就停下（使用者曾從別台電腦發過版）。
2. 改 `tauri.conf.json`、`Cargo.toml` 的版本號（不會加 BOM）。
3. 跑 `scripts/check.ps1`，過了才 commit（`版本 X：…`＋`Co-Authored-By`）、打標籤、推上去；CI 也會再跑一次 check，過了才打包安裝檔。

## 原則（使用者定的）

- **寧可少遮，不能多遮。** 多遮了重出也沒用。改遮罩或切段邏輯之前，先用舊資料離線驗證。
- 畫面上的說明要講人話、越短越好，詳細的放 `docs/使用說明.md`。
- 改完要自己驗證過再回報，不要只說「應該可以」。

## 離線驗證方法

程式有隱藏的批次模式，不開視窗、直接跑一次監看：

```bash
keyword-title-tool.exe --autocut-batch cfg.json
```

`cfg.json` 範例：

```json
{"watch_dir": "\\\\<側錄主機>\\<分享>\\2026_11_09", "stills_dir": "C:\\Users\\user\\Desktop\\關鍵遮蓋",
 "output_dir": "<輸出資料夾>", "titles": {"kind": "File", "value": "<文稿.txt>"},
 "auto_render": false, "make_all": false, "since": "21:50", "end_cutoff": "23:59:30",
 "rotate_secs": 5.0, "ai_key": null, "gain_db": 0.0, "watermarks": []}
```

- 把舊的掃描快取（`.autocut/*.cache`、`*.ocr.tsv`、`seams.tsv`、`ai.tsv`）複製到 `output_dir\.autocut\`，就不用重掃，幾分鐘就跑完。
- 看 `report.txt` 裡「第 N 段：長 …」那幾行，比對改之前、改之後。
- 基準資料：
  - **11/09**：側錄 `\\<側錄主機>\<分享>\2026_11_09`（實際位址問使用者，不寫進 repo），遮蓋圖在桌面 `關鍵遮蓋`。
    - 正確結果：第 1 段 30:45.777（05:06.1–35:51.9，跟手剪的一樣）、第 2 段 14:02.141、第 3 段 4:40.514、第 4 段 37:49.601、第 5 段 8:40.653、第 6 段 5:40.507。
  - **11/06**：第 1～6 段 26:53.312、20:04.470、2:37.924、38:07.585、11:15.008、3:03.583。
  - **11/10** 狀況很多，使用者說先不要拿來測。
- 共用資料夾：設定頁「共用資料夾同步」填的路徑下的 `MMDD關鍵`（實際位址問使用者，不寫進 repo）。這個路徑在 bash 裡會亂掉，要用 PowerShell。
- 工具用的 ffmpeg 在 `%LOCALAPPDATA%\tw.ebc.keyword-title-tool\tools\`。
- 批次模式是視窗程式：PowerShell 用 `&` 叫**不會等它跑完**，要用 `Start-Process -Wait`（golden.ps1 已經這樣做）。

## golden 測試

`scripts/golden.ps1` 用固定樣本重跑自動切段，跟確認過的答案比：段落起訖差超過 1 格、或**多遮**（答案沒遮的地方遮了）就失敗；少遮只警告。

- 樣本在 `D:\kwt\golden\<案例>\`（太大不進 repo；別台電腦把整個資料夾複製過去，側錄要連得到）：
  - `case.json`：`{"watch_dir": "側錄資料夾", "since": "21:51", "end_cutoff": "23:59:30"}`
  - `titles.txt`（當天文稿）、`stills\`（當天的靜圖，凍結不再動）
  - `cache\`（掃描快取，-Update 時存進來）、`expected.json`＋`expected-report.txt`（答案）
- 目前的案例：**1112**（since 21:51，第 1 段要往前找開頭、第 6 段開頭跨檔找 Logo）。答案是 0.6.38 的結果：6 段、19 個遮罩，第 6 段 2:51.038。1106、1109 的文稿和靜圖已經被清掉，做不了。
- 建新案例：放好 case.json、titles.txt、stills\ 後跑 `golden.ps1 -Update`，**看過 expected-report.txt 確認是對的**再當答案。
- 改的是遮罩判斷、答案應該要變時：先用改之前的版本建答案（`-Exe 舊版.exe -Update`），再用新版比，逐條看多出／少掉的遮罩對不對，確認後才 -Update。
- 靜圖簽名改了（例如新增靜圖種類）快取會作廢重掃，一個案例約 15 分鐘。

### 0.6.35 細節（最新改動）

**11/09 事件：** 第 1 段只出了 17 秒。原因是節目開頭有 14 秒的開場提要（主持人先念第 1 段的標題），舊邏輯「一段只取第一個區塊」就拿了它，真正的第 1 段反而被當成重播丟掉。

**修法：** 改在 `plan.rs` 的 `plan_segments`。

- `titles.rs` 新增 `which_line`，OCR 不只對到第幾段，也對到是那一段的第幾條標題。
- 同一段出現好幾次時，選法照這個順序：
  1. 取有播到這段文稿**最後兩條標題**的那一次。
  2. 都還沒播到（還在錄），就取第一次。
  3. 但如果後面那次長兩倍以上，改取後面那次。
- 安全網：
  - 沒播到最後標題、已經播完、又短於 60 秒（`MIN_SEGMENT_SECS`）→ 不當成一段，不出片。
  - 後面還有同一段正在錄 → 先等。

**從幾點開始看**（`autocut.rs` 的 `since_clock`、`list_files`、`replan`）：

- 填 `HHMM` 或 `HH:MM`：從這分鐘以後開始錄的檔才讀。
- 填到秒：從包含這一秒的那個檔開始讀。
- 那一刻有一段正在播時：
  1. 往前走到連續 5 秒沒有標題條的地方，當成這段的開頭。
  2. 開頭不在讀到的檔裡，就每輪往前多讀一個檔（`lookback`，最多 `MAX_LOOKBACK` = 6 個）。
  3. 加了 `lookback_listed` 這個欄位，確保一定要等前一個檔真的讀進來才再往前讀；沒有它的話，一輪裡會連跳 6 次。
  4. 6 個都讀完還是找不到開頭，才判成不完整、不出片。

**時間只打數字：**

- 前端是 `autocut.js` 的 `acDigitsTime` 和 `acDigitsRanges`，只掛在要填時間的欄位：從幾點開始看、最晚幾點結束、BAR 時段、手動遮罩時段、串接影片的開始／結束。
- Rust 的 `parse_clock` 也收只打數字的寫法（例如 `2359`）。

## 已知限制／可以再做的

- 往前找開頭要靠前後有 5 秒以上沒有標題條（廣告、轉場）。哪天兩段之間完全沒有，就分不開。
- 同一支素材換了鏡頭（遠景、近景）比不上截圖，只能靠多截幾張或手動遮罩。
- 開「跳過棚內」或 AI 補判要有 Gemini 金鑰。一集大約問一百多次，免費額度可能會被打爆（429）。
- 使用者不要「強制完整」按鈕，「從幾點開始看」也只要全域一個就好，不用每段各一個。
